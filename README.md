# Multiscale reliability importance measures under uncertain network disturbances

## A quantum-walk-inspired numerical framework

Reproducible numerical experiments for the manuscript by **Junxiang Xu**.

The code evaluates finite-horizon propagation diversity, threshold probabilities and signed importance for edges, corridors and regions. It includes second-order interactions, dependent disturbances, classical diffusion comparisons and an independent directed travel-service assessment.

## 1. Install

Use Python **3.11** and a separate environment:

```bash
git clone https://github.com/JUNXIANGXU666/Multiscale-reliability-importance-measures-under-uncertain-network-disturbances.git
cd Multiscale-reliability-importance-measures-under-uncertain-network-disturbances
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

## 2. Obtain the original data

The only external dataset is **Sioux Falls**, from the [Transportation Networks for Research repository](https://github.com/bstabler/TransportationNetworks/tree/master/SiouxFalls):

| File | Used for |
| --- | --- |
| `SiouxFalls_net.tntp` | Directed arcs and free-flow travel times |
| `SiouxFalls_node.tntp` | Benchmark node coordinates |
| `SiouxFalls_trips.tntp` | Origin–destination demand and source weights |

Read the [upstream data terms](https://github.com/bstabler/TransportationNetworks#license), then download the files:

```bash
python fetch_data.py
```

The script obtains these three files directly from the original repository and verifies their SHA-256 hashes. Alternatively, download them manually into `data/sioux_falls/`. Exact URLs and expected hashes are in `data/sources.json`. Raw TNTP files are not redistributed here.

The three small processed CSVs in `data/sioux_falls/` preserve the physical-edge mapping, source weights and 797 candidate definitions used in the service experiments. Motifs, the spatial grid and synthetic networks are generated by the code. Sioux Falls coordinates are artificial benchmark coordinates, not a georeferenced road inventory. See [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt).

## 3. Check the installation and regenerate figures

```bash
python reproduce.py verify
python reproduce.py test
python reproduce.py figures
```

These commands check release integrity, run small numerical tests and regenerate all eleven figures from the compact reference results. Outputs appear in `runs/reference/figures/`. They do **not** rerun the full experiments. The tests cover propagation probabilities, derivatives, travel-service calculations, batched calculations and statistical routines.

The plotting scripts use Arial when available and DejaVu Sans otherwise. Fonts affect appearance, not numerical results.

## 4. Recompute the experiments

```bash
python reproduce.py all --mode fresh --confirm-long-run
```

This creates `runs/fresh/` and executes the complete experiment sequence without copying saved reference results. It can require many hours. Scenario arrays, checkpoints, tables and figures are generated locally. An interrupted service calculation resumes its unfinished units when the same command is repeated.

For the independent travel-service assessment alone:

```bash
python reproduce.py service --mode fresh --work runs/service_only --confirm-long-run
python runs/service_only/service/experiments/analyse_service_validation.py
```

Use a new `--work` directory for a separate run. Seeds and numerical settings are fixed in the source and `config/service/`. Training and calibration each use 4,096 states. The main held-out experiment evaluates 797 candidates with 1,024 shared scenarios. Allocation and direction comparisons each use 512 scenarios. The service target is based on directed shortest travel times under the specified slowdown law, not observed road failures or equilibrium traffic assignment.

## Code and results guide

| Paper section | Code | Reference results |
| --- | --- | --- |
| 6.2 Travel-service assessment | `code/service/` | `reference/service/` |
| 6.3 Coefficients and analytical intervals | `run_all_experiments.py`, `sioux_and_sensitivity.py`, `kernel_dependence_experiments.py` | `reference/dpc/` |
| 6.4 Grid importance and approximation | `run_all_experiments.py`, `kernel_dependence_experiments.py` | `reference/dpc/baseline/` |
| 6.5 Parameter, dependence and topology comparisons | `sioux_and_sensitivity.py`, `propagation_scale_audit.py`, `kernel_dependence_experiments.py` | `reference/dpc/` |
| 6.6 Sioux Falls comparison | `sioux_and_sensitivity.py`, `kernel_dependence_experiments.py` | `reference/dpc/sioux/` |
| 6.7 Computational cost | Runtime phases of the DPC scripts | `reference/dpc/robustness/` |

DPC scripts are in `code/dpc/`. `dpc_core.py` contains the propagation and importance calculations. `service_validation.py` defines the independent service measure. `reproduce.py` prepares the working layout and runs the modules in order.

The `reference/` directory contains only the compact summaries and plotting inputs needed for quick checks. Full scenario arrays and complete run outputs are deliberately omitted. Fresh runs produce them for numerical reanalysis. Floating-point results can differ slightly across numerical libraries. Timing and memory results depend on hardware. Classical comparisons and negative results are retained.
